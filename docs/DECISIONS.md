# Decision log — claude-codex-bridge

Built 2026-09-06; hardened 2026-09-07 after an eleven-seat audit (see `docs/audit/`). This is the complete record of what was decided, why, what was rejected, what was verified, and what was not. It exists so that independent reviewers (human or model) can audit the decisions, not just the code.

## 1. Requirements as stated by the owner

1. Use Claude Code (Claude Fable 5.1) to write code and have OpenAI's frontier model audit it; later broadened to "call either model from either side for anything hard".
2. Auditors wanted: GPT-6 Astra at `ultra`, GPT-5.6 Sol at `ultra`, Claude Opus 5 at `max`. Model and effort must be independently selectable per run, with any number of seats.
3. Account-agnostic: must work on any machine with whatever Claude and ChatGPT accounts are signed in there (the owner has several of each across six Macs; friends should be able to use it too). Setup tokens acceptable. Nothing may be bound to one account or an API key.
4. Minimize latency, maximize output quality, keep every model's context small (Opus 5 degrades as context grows).
5. Distributed through the owner's GitHub skills repository (synced to all machines) and installable by other people.
6. Not named `/audit`; `/codex` or `/gpt`. Both sides must be able to call each other.
7. Monitor every seat's context window, even a Codex process from inside Claude Code. **Status: met for Claude seats (exact, per call); not met for Codex seats** (see A7 and section 6). The owner has not yet accepted a requirement change.
8. (2026-11-07) The bridge always uses the latest GPT models without anyone editing `models.json`: a newer model that a signed-in account's catalog lists becomes its family's head automatically and visibly (A28). This overrides, for GPT promotion only, the earlier rule that a head moves only by a human checkpoint.

## 2. Facts established before designing (verified on the machine, 2026-09-06)

- `codex` was not on PATH. The CLI ships inside the ChatGPT desktop app at `/Applications/ChatGPT.app/Contents/Resources/codex` (bundle id `com.openai.codex`), sharing `~/.codex` with the app. The account is a ChatGPT Pro subscription, `auth_mode = chatgpt`, no API key.
- GPT-6 Astra shipped 2026-09-03 (`gpt-6-astra`). The local model picker hid it, but `codex exec -m gpt-6-astra` worked on this account. Codex ≥ 0.153.1 required; the app updated its bundled Codex from 0.152.1 to 0.153.1 during the session and later shipped 0.153.4.
- Codex effort tiers: `low medium high xhigh max ultra`; `ultra` = "maximum reasoning with automatic task delegation" (Codex spawns subagents). Luna stops at `max`. "Altera" in the owner's dictation = `ultra`; "Astro" = Astra.
- `codex mcp-server` prints a deprecation warning. OpenAI's replacement is the app server; OpenAI's official Claude Code plugin (`openai/codex-plugin-cc`) wraps it. That plugin's `/codex:review` cannot take model or effort flags and its effort parser stops at `xhigh`.
- `claude mcp serve` exposes Claude Code's tools, not Claude's judgment.
- Measured: `codex exec` cold start 3–5 s; deprecated MCP path 11 s. On a 20-line, three-bug diff: Astra@max 95 s / 84k input tokens; Astra@ultra 100 s / 130k; Terra@max 108 s / 102k; Sol@ultra 109–226 s / 244–263k; Opus 5@max 173 s (found a fourth bug); Luna and Terra @medium 32–43 s and both missed a bug that Opus and Sonnet@low caught.
- Claude Code: `--allowedTools` grants permissions but does not restrict the tool inventory; `--restricted` plus `--tools` plus `--strict-mcp-config` does, and drops inherited settings and MCP servers (measured startup context 4,437 tokens versus 28,990 by default; subscription login still works; an empty `CLAUDE_CONFIG_DIR` is "not logged in"). `--restricted` cannot be combined with the bypass-permissions mode. `claude -p` reads the prompt from stdin. `--json-schema` rejects a schema carrying the draft-2020-12 `$schema` header.
- Codex ≥ 0.153.4 refuses MCP tool calls in non-interactive `codex exec` unless the server has `default_tools_approval_mode = "approve"`; per-tool overrides live under `[mcp_servers.<name>.tools.<tool>]`. `codex exec resume` does not accept `-s`; the sandbox must be pinned with `-c sandbox_mode=…`.
- Exporting `CLAUDE_CONFIG_DIR`, even set to the default `~/.claude`, makes `claude auth status` report `loggedIn: false` on a signed-in Mac; Claude Code resolves credentials differently whenever the variable is present. The bootstrap therefore exports it only when the caller had it set (found 2026-09-07).
- Anthropic's guidance on subscription use of the Agent SDK is not categorical (some subscription-backed SDK use is allowed); the SDK was rejected here on portability and dependency grounds, not only on login grounds.

## 3. Architecture decisions

| # | Decision | Alternatives rejected | Why |
|---|---|---|---|
| A1 | Call GPT through `codex exec` per seat (JSONL events, `--output-schema`, `-o`, persisted threads for `reply`). | `codex mcp-server` in Claude Code; a custom app-server client; OpenAI's plugin alone. | Deprecated and slow; more engineering for a ~3 s gain; cannot pin model/effort per review. |
| A2 | Call Claude through `claude -p --output-format stream-json` per seat, under the restricted profile (A13). | In-process subagents; the Agent SDK; API keys. | Subagents cannot be launched from Codex or a shell and give no live token stream; the SDK adds a dependency and a second auth path; keys violate the account-agnostic requirement. In-process subagent variants are kept as optional extras. |
| A3 | One engine with "seats" `model[:effort][@fast]`, any number, each a separate OS process **group** with its own fresh context. | A coordinator subagent that fans out (built first, then removed). | Isolation by construction, identical from both sides, monitorable. |
| A4 | Reverse direction (Codex → Claude) through a small stdio MCP server that shells out to the engine, registered in Codex as `claude-bridge`. | A skill telling Codex to run the CLI in its sandbox; `claude mcp serve`. | Codex's sandbox blocks network and writes to `~/.claude`; MCP servers run outside it. |
| A5 | One findings schema for every seat; `merge_findings.py` clusters by exact repository path, line proximity and vocabulary evidence, marks consensus, and keeps every member visible. | Free-text reviews side by side. | Attribution and consensus become mechanical; nothing disappears in a merge. |
| A6 | Defaults: single seat `astra:ultra`; review and council `astra:ultra,sol:ultra,opus:max`; from Codex `fable:max` (ask/task) and `opus:max` (review). Overridable per machine via environment variables. | Astra@max as default. | The owner explicitly chose ultra for both GPT seats. |
| A7 | Live monitoring from per-seat status files written while parsing each process's stream: Claude seats give exact context size after every model call; Codex seats give activity live and per-turn totals. **Codex context occupancy is unimplemented**: `codex exec` does not expose it; the table says "n/a" rather than showing totals as context. | Polling Codex's app-server telemetry. | Not available through `codex exec`; would require the daemon path. |
| A8 | Packaging: canonical directory `claude-codex-bridge/` inside the owner's skills sync repo, laid out as a Claude Code plugin, with root-level symlinks so the existing `link.sh`/autopush machinery distributes it; `publish.sh` for a standalone public repo. A marketplace install exposes namespaced commands (`/claude-codex-bridge:codex`). | A separate repo from the start. | The sync repo already reaches every machine; the plugin layout makes the same directory installable by anyone. |
| A9 | `codex` on PATH via a wrapper **script** (never a symlink) written fail-closed by the bootstrap; the engine and the bootstrap validate any candidate with a `--version` probe under a timeout and prefer `CODEX_BIN`, then a standalone install, then the app's bundled Codex. | Symlink; always npm. | Codex resolves helper binaries next to its real executable; a symlink broke the code-mode host; the probe catches a damaged launcher. |
| A10 | Auth: local logins; `claude setup-token` / `codex login --device-auth` for headless machines; `CODEX_HOME` / `CLAUDE_CONFIG_DIR` for two accounts. The engine preserves the authentication variables and forwards them into the MCP server. | Central token store; API keys. | Most interoperable; least to maintain. |
| A11 | OpenAI's official plugin installed alongside (optional). | Not installing it. | Adds `/codex:adversarial-review` and `/codex:rescue`; colon-namespaced, no collision. |
| A12 | Reviewer prompts: defect-first rubric, the author's INTENT written by the caller, optional FOCUS, and a **frozen patch** (A14) that every seat reads; the caller relays bounded output and asks before fixing. Intentional behavior changes are exempt only when they do not break a documented requirement or a security invariant. | Pasting the diff; auto-fixing. | Seats are agents with repo access; the frozen patch keeps inputs identical and small. |
| A13 | Claude seats run `--restricted --tools <list> --strict-mcp-config --add-dir <job dir>`; read-only seats get `Read,Grep,Glob` and no shell; write tasks add edit tools and a shell allow-list with `git commit`/`git push` denied; the unsandboxed mode is Codex-only. | `--allowedTools` alone. | Measured: `--allowedTools` never restricted anything; the restricted profile is enforceable and six times cheaper at startup. |
| A14 | Review input is frozen: the engine captures one patch (staged, unstaged and untracked work, or the commit range) with external diff, text conversion and pagers disabled, fingerprints it, hands the same file to every seat, and flags drift if the tree changed before the seats finished. | Each seat running its own `git diff`. | Seats otherwise review different code minutes apart and the merge still reports consensus. |
| A15 | The reverse bridge auto-approves only read-only tools; `claude_task write=true` needs a Codex approval prompt (per-tool `approval_mode = "prompt"`) and a server started with `CLAUDE_BRIDGE_ALLOW_WRITE=1`; arguments are schema-validated; cancellation and deadlines kill process groups. | Blanket approval. | Any Codex session could otherwise have Claude edit files outside the sandbox with no human gate. |
| A16 | Process discipline: watchdog timers, process groups, durable cancel (marker file, PID identity by start time, terminal state preserved), exception boundaries, `0700`/`0600` job files confined to the jobs root, checked git with verified revisions, exit codes 0/3/1/2, and the owner's usage-limit ladder (20 s × 2, then hourly, interruptible). | Best-effort handling. | These were the audit's P0/P1 lifecycle findings. |
| A17 | Union merging in the sync repo applies to prose under the plugin only; code, structured files, and since 2026-09-07 also `SKILL.md`, agent definitions and reviewer prompts use the normal three-way merge. | The blanket union rule. | Two machines could otherwise splice conflicting Python, or contradictory model instructions, silently. |
| A18 | A Claude write seat has no shell unless `task --write --shell` (or `reply --write --shell`) is passed; `--shell` adds a Bash tool with an allow-list (git status/diff/log/add, test runners) and direct `git commit`/`git push` denied. `--with-user-config` is honoured only for write tasks. | Always giving write seats the allow-listed shell. | The allow-list matches *direct* command lines only: an allowed interpreter (python, node, a package manager) can still spawn anything, so the shell is instructed, not confined, and the filesystem is not confined either. Most edit tasks need no shell, so the default is the smaller capability and the caller opts in per task. |
| A19 | Usage-limit retries are iterative (no recursion), a seat on the ladder is in state `waiting` with `waiting_until` and its supervisor's identity, `cancel` interrupts the wait, and a seat that had already started working is **resumed** in its own thread or session with a continuation instruction rather than relaunched. A limit hit after work began with no thread to resume fails the seat with an explicit message. | Relaunching the same prompt after every wait. | A relaunched write task would repeat edits and commands already made; resuming keeps the work and the seat's own context. |
| A20 | The Codex-side skill lives at `codex-skills/claude/` inside the plugin, not under `skills/`; the bootstrap and ownership checks accept both layouts for older installs. `claude_review`/`claude_task` accept `wait: false` (detached engine, job id returned at once) and the server gained `claude_status`/`claude_result`; the server confines `cwd` and `files` to an authorized root and kills recorded seat processes (identity re-checked) when it kills the engine. | Leaving it under `skills/`; always waiting inside the tool call. | Claude Code discovers every plugin skill under `skills/`, so a Codex-only skill leaked into Claude's skill list; long jobs died with the MCP request deadline. |
| A21 | `CODEX_BIN` and `CLAUDE_BIN`, when set, are authoritative (no fallthrough to other binaries); every Codex candidate must pass a capability probe (`exec --help` lists `--json`, `--output-schema`, `--output-last-message`). Review input above 4,000 diff lines is refused without `--allow-large`; `--intent-stdin` keeps the author's text off the command line; a failed merge makes the exit status partial and is named in the footer; every mode finalizes its job under an exception guard; a reply recomputes the job state from the original seats. | Silent fallthrough; warning only on large diffs; treating a merge failure as a clean review. | The test suite once fell through from a stub to the real Codex and spent tokens; a too-old CLI would fail mid-job; a clean-looking report after a merge failure is a false negative. |
| A23 | `BRIDGE_ROOT` (environment): when set, the engine refuses any effective working directory outside it (including a reply's recorded directory), stops the git-top-level promotion at that boundary (the given subdirectory is kept and review capture is limited to its subtree, with repository-relative paths throughout), and the MCP server sets it to its authorized root on every launch (dropped only under `CLAUDE_BRIDGE_ALLOW_ANY_CWD=1`). Process groups are signalled only with proof of ownership: a live leader, or for a leaderless group a `ps` membership check that every member started inside the leader's lifetime (at or after the recorded leader start, and no later than the moment its exit was observed); without an upper bound, or without `ps`, the group is left alone, and `cancel` touches a leaderless group only when its supervising engine is gone. Codex runs sandboxed commands in their own sessions, outside the seat's group, so every kill path (timeout, cancel, global shutdown) first snapshots the live leader's descendant tree (only when the snapshot's root carries the recorded leader identity) and sweeps those groups too; immediately before each signal a descendant's identity and its current group membership are re-read (per entry, not per round), a group is signalled at most once per round, and a descendant that left its recorded group is signalled alone. `cancel` bounds a leaderless group's member window by the moment it first observed the leader gone, and global shutdown re-observes the leader before every escalation round. The child is registered before any identity query so a signal in that window still finds it; the stdout reader is interruptible (`select` + `os.read`) and joined with a bound, so a refused cleanup never leaks a blocked thread. A seat with no live child but a verified live supervisor (between attempts, on the ladder) is live. The event reader keeps reading after the leader exits only while lines keep arriving (five-second idle, sixty-second cap), then stops the producer and kills the group, but still processes everything already buffered. Usage limits are classified from the last UNRECOVERED structured diagnostic when one exists and from stderr only otherwise (a recovered error does not hide a later stderr-only limit). The review inventory describes the reviewed revision and always includes changed and deleted paths; the drift fingerprint hashes untracked contents. Replies register and retire under one job-wide lock; a merge failure keeps a job partial through later replies. A seat whose review output is not parseable JSON is a failed seat; `result` exits with the persisted outcome; the bootstrap forwards `CLAUDE_BRIDGE_ROOT`, `CLAUDE_BRIDGE_ALLOW_ANY_CWD`, `CLAUDE_BRIDGE_TOOL_DEADLINE`, `CLAUDE_BRIDGE_ALLOW_WRITE` and `CLAUDE_BRIDGE_ENGINE` through the registration's `env_vars`. | Trusting the server's check alone; leader-gated termination; signalling any live PGID; latching any limit message. | The server validated a subdirectory while the engine silently adopted the repository above it; a leader that exits first shielded its descendants; a reused PGID could otherwise be signalled; a recovered 429 sent unrelated failures onto an unbounded ladder; a prose answer to a review counted as a clean review; ignored files remain outside the drift guarantee. |
| A24 | Distribution to friends is a plain zip built by `package.sh` (one folder, `VERSION` stamp, no audit records) and installed by `install.sh`, which runs the bootstrap in a third mode, **standalone**: chosen automatically when the folder is neither a repository-sync checkout nor a marketplace install, it creates the four Claude-side links and the Codex skill link into the unzipped folder under the same ownership-checked transaction as every other link, and `--uninstall` removes exactly what the folder owns. | A28 | **Automatic promotion of GPT heads (2026-11-07, Kevin's requirement 8).** The check's refresh, under the evidence lock, runs a promotion pass over the Codex catalog it has just read (on every `doctor`, and before a model-starting mode when the daily re-check is due or the last pass, `promotion_pass_at` in the evidence file, is older than the re-check window; a `doctor` that waited behind another process's refresh runs its own when that one skipped the pass, as an older engine or `BRIDGE_MODELS_PROMOTE=off` does); a step it takes goes into a ledger beside the evidence store (`models-evidence.promotions.json`, 0600) and every reader of the table (the engine, doctor, triad) loads `models.json` with the ledger applied (`bridge_models.load_table`). A model is adopted for a family when the catalog counts (read in this refresh; every catalog configuration key at its default; `account/read` in the same app-server session confirms a login, because a signed-out Codex lists its bundled catalog; the reading CLI's version parses) and the model is: `hidden: false` explicitly; named by the family's `id_glob` with a dotted number for the `*` (not `gpt-<n>-mini-terra`, not a codename); unknown to the table and not refused; not blocked on this Mac by an undone promotion; free of any lifecycle statement (status other than active/current/available, deprecated flag, upgrade pointer, retirement date, deprecation prose) and of any sticky marker; offering only Codex efforts and every effort the current head offers; and of a strictly higher generation (numeric, trailing zeros ignored). The highest candidate wins and lower ones become retired predecessors; two of one generation hold the family back. The new record's floor is the reading CLI's exact version (a prerelease allowed for these records only: the bootstrap reads the shipped table, whose floors stay X.Y.Z). The previous head becomes a retired predecessor (refused as superseded); fallback edges follow the heads and are dropped where they would descend. A `models.json` that names the model (a human checkpoint) takes over and the step is skipped; the models the step superseded stay retired predecessors only while the head is at least as new (a checkpoint that refuses the step's model without moving the head leaves a newer runner-up a candidate again). Nothing is demoted automatically: a `models.json` that moves the head below this Mac's promoted model without naming it leaves the promoted head in force, and `doctor` says so. Visibility: a stderr line when a step is taken, doctor's `promotions:` block (steps, skipped steps, blocked models, the last pass and every model it held back with the reason), the heads line marks promoted heads, each new job or reply whose seat runs one (directly or through its `|` preference list) leads with `NOTICE: models: <family> runs <id>, promoted automatically ...` once, for seven days after the step, and a seat's `expected_evidence` names the promotion. `doctor --undo-promotion <family> --reason` removes the family's latest step and blocks only its model on this Mac (refused by name, reported as `info`, never promoted again here) until a `models.json` names it; another newer model the catalog lists stays a candidate, and when the same doctor's check adopts it (promotion on, the catalog read), doctor says so in a `then:` line (a block of a model the user never rejected would hold a newer model back for good). A block of a family a later `models.json` dropped is ignored. A seat with no capable account for a promoted head says where the head came from and how to undo it. ## 3a. 2026-10-13 — the capacity gate, the throttle class and the computer-use lease (build spec of 2026-10-13, lane B)

**Why.** On 2026-10-12 a batch run of about 120 concurrent `bridge.py task --seats sol:ultra` seats (`BRIDGE_ROUTER=off`, so relay's per-account slots never applied; about 300–400 live Codex sessions counting each ultra seat's 2–3 subagents) shared one ChatGPT login with three computer-use tasks. ChatGPT answered "exceeded retry limit, last status: 429 Too Many Requests", Codex's Chrome plugin failed closed and the computer-use tasks never ran. The bridge made it worse: `LIMIT_RE` matched the 429 as a usage limit, so unrouted seats retried in lockstep (20 s, 20 s, 3600 s, no jitter) and routed seats called `relay hit` on a healthy account and failed over, pushing the herd onto the next account. "Connection refused" was not recognised at all.

**What.**
- A throttle class evaluated before the usage-limit regex, from the turn.failed message (or the final error event of a run the watchdog killed), never from stderr: `codex-throttled` (retry limit with last status 429/5xx, 429 Too Many Requests, 503 Service Unavailable, high demand, model at capacity, Flex capacity unavailable, server_overloaded) and `codex-network` (connection refused/reset, unreachable, DNS, stream disconnected, error sending request to chatgpt.com, waiting for network; the WebSocket-403 reconnect row only for a killed run). Such an attempt never calls `relay hit`, never fails over and never enters the usage-limit ladder; it records a pacer trigger and waits on its class's ladder (batch 300/900/1800 s then every 1800 s ×0.8–1.2, unbounded; interactive 60 s then 300 s ×0.6–1.4, then the seat fails: reviews never wait on Codex), resuming its thread if work began. A throttle line in the stderr tail is no longer read as a usage limit either (the attempt then fails plainly; the batch drivers' own transient-backoff handles that line). The usage-limit ladder is jittered ×0.6–1.4. Throttle and capacity waits are not charged to `--timeout`.
- Launch classes `interactive|batch` (`--class`, `BRIDGE_CLASS`; fanout defaults to batch, everything else to interactive) with a self-limiting interactive budget.
- A capacity gate inside `run_codex_seat`'s attempt loop, after the account is settled and before `_codex_attempt`, so every retry, failover, busy relaunch and reply is re-admitted on the home it really uses, parks through `_wait_seat` (visible, cancellable) and releases its ledger entry in a `finally`. Admission is decided under one flock per account (`<capacity dir>/<key>.lock`, key = sha256 of the realpath of CODEX_HOME): the pruned admission ledger (pending weight admitted < 180 s ago), the rollout-based live-session count (4.2; cached 5 s), the priority lease (4.1, a shared-lock probe of the runner's holder files plus host-matched unexpired reservations; the bridge never writes or prunes there), the PAUSE file and the pacer (wake quiet period, TCP probe, ramp slots, minimum gap). Batch admits only below cap − reserve with no lease, no PAUSE and the pacer's leave; interactive admits within the cap and is held only by a failed network probe (≤ 120 s) and the hard cap (≤ 900 s, then a clear failure line).
- Visibility: activity lines in plain words, one `[bridge] capacity:` stderr line per change of cause, one capacity notice per job, `events.jsonl`, and a capacity section in `doctor` and `status`. `reply` to a waiting seat names the real cause (old seat files still read as a usage limit).

**The numbers and who sets them.** Defaults: session cap 100 (about 35–45 ultra seats, well under the ~120 Kevin approved on Oct. 12; the service refused at about 130), interactive reserve 16, interactive budget 24, ultra weight 3, cap_mode **shadow** (Kevin's cautious-rollout rule: the session-count limits log "would hold" and admit until he flips `cap_mode` to `enforce`; the lease, PAUSE, pacer and throttle class are enforced from the first install). The cap is Kevin's decision in `~/Library/Application Support/legal-research/codex-capacity.json`; the build does not depend on its value.

**Rejected.** Gating in `_start()` (knows neither the home, the class nor the job and cannot park cancellably); counting sessions from `ps` (subagents run in-process, npm seats show as two processes); a lease judged by pid + start time without a lock (pid reuse, stale after a crash); charging holds to `--timeout` (a long hold would trip the watchdog on a just-started batch seat and burn the driver's attempt budget); ending a batch hold with an error (the Oct. 12 driver classes anything unknown as a real failure).

**Fix round 1 (2026-10-13, review findings B-1..B-7 and O2/C-8).** The ramp's end is decided by comparing elapsed steps against the doublings needed before any exponentiation, and a finished ramp is cleared from the pacer (pacer state a day old used to raise OverflowError in every batch admission and in doctor/status). A throttled attempt that had begun work pins the seat to the account holding its thread for every retry, busy refusals included, as a reply is. After a hold, the model check (and a pinned seat's stale sign-in verification) runs again right before the launch, inside the ledger-release `finally`. The routed wait budget follows the live seat Clock (both move with uncharged waits; `BRIDGE_ROUTED_MAX_WAIT` is still its own limit). The class a seat was admitted as (batch for an interactive seat over the interactive budget) drives the network hold and the throttle ladder. The whole admission interval is uncharged, credited once at its end. The once-per-job capacity notices are checked and appended under one job lock. The live-session counter drops the tail's first segment only when the read starts inside a line, grows the 64 KiB tail once to 1 MiB when it holds no boundary, and reports ints: `long_turns` (no boundary within the grown tail, lines parsed: the normal long turn), `degraded` (no complete line parsed at all) and `stalled_in_turn` (a task_started untouched for over 120 s); the runner's copy behaves identically. Test knobs `BRIDGE_HOLD_POLL` and `BRIDGE_NETWORK_HOLD_INTERACTIVE` shorten the hold re-check and the interactive network hold.

**Not verified.** The gate against a real fleet and a real computer-use lease (the runner's holder files are lane R's; this lane's helper reproduces their lock discipline); `kern.waketime` on a Mac that actually slept (the Mini reports 0); the cap number itself.

## 4. Incident during the build (2026-09-06)

Re-running the bootstrap to "upgrade" the PATH shim from a symlink to a wrapper script wrote the script through the still-existing symlink, replacing `/Applications/ChatGPT.app/Contents/Resources/codex` (a 220 MB signed binary) with a 167-byte script that exec'd itself. Recovery: the official app archive (`ChatGPT-darwin-arm64-26.901.51231.zip`, sha256 matched Homebrew's cask) was downloaded, its signature verified, and the binary restored. Overwriting the old inode in place made the kernel SIGKILL the binary ("Taskgated Invalid Signature"); replacing via a new file + rename fixed it. With the owner's approval the whole app bundle was then replaced by 26.901.51231 (signature valid, Gatekeeper accepted). Safeguards now in the bootstrap and proven by tests: never write through a symlink; refuse destinations inside an application bundle or outside the home directory; back up, never delete, an unrelated file; validate any launcher with a timed `--version` probe; `--check` changes nothing.
